# 使用計劃與提醒（0.4.0）

## 開始使用

1. 安裝 `output/QuotaPocket-debug.apk`，開啟底部「使用計劃」（0.5.0 導覽）。
2. Claude／Codex 的 5 小時／每週額度各有一組設定。點時段，修改後按底部「儲存計劃」。
3. 返回「使用計劃」→「用量提醒」，開啟提醒總開關，允許系統通知。也可從「設定」→「通知設定」進入。首次使用提醒功能時總開關預設關閉；已儲存的選擇在更新 App 後保留。
4. 按「發送無聲測試通知」，下拉手機通知列查看。測試不使用真實用量，也不修改提醒紀錄。

總開關與重置開關立即儲存；個別計劃需按儲存。離開尚未儲存的編輯頁會先確認。各組可分別停用監控、超用提醒或少用提醒。

## 三種計劃

| 計劃 | 設定與計算 |
| --- | --- |
| 平均分配（預設） | 計劃已用 = 本週期已經過的時間 ÷ 週期長度 × 100%。以來源的重置時間減去 5 小時／168 小時作為週期起點。 |
| 按星期分配 | 週一至週日各填 0–100 的相對比重，2 是 1 的兩倍，0 表示不安排。按手機時區及各日期實際涵蓋的時數加權，再正規化為本週期的 100%。不是每逢週一重新開始，也不是每個日曆日給固定百分比。 |
| 保留額度 | 設定「距重置幾小時前」與「至少保留多少 %」。此前線性分配可用部分，之後線性分配保留部分。例如每週距重置 48 小時前保留 30%，前 120 小時分配 70%，後 48 小時分配 30%。 |

星期比重至少一天需大於 0。跨午夜及夏令時間以實際經過的時間計算；5 小時週期完全落在同一天時，相同比重抵消，效果與平均分配相同；整個週期皆為零比重時，計劃已用為 0。保留目標的時間跟隨來源週期移動，並非某個固定日曆日期。

## 偏離與避免重複通知

- 實際已用 = 100 − 來源剩餘百分比。
- 偏離 = 實際已用 − 同一資料時間下的計劃已用；正值超用，負值少用。
- 差距單位是「百分點」。計劃已用 40%、實際 55%，是超用 15 個百分點。
- 超用與少用門檻預設各 10 個百分點；再次提醒的加劇間距預設 10，均可設定 1–100。
- 例如門檻 10、間距 10，達到 10、20、30 時各提醒一次。由 9 直接跳到 35，只送一則，記錄最高已到達的級別。
- 兩個方向各自記錄最高級別。回到正常範圍，再偏離同一級別，不會重新通知。新週期清空級別。
- 每組時段在通知列保留一則最新提醒；點通知可直接編輯對應計劃。未處理的舊通知會被較新提醒更新。
- 修改計劃／門檻會重建該組紀錄，依目前有效資料重新判斷，可能立即發出新的偏離提醒。原樣儲存不清除紀錄。
- 關閉總開關會清除提醒紀錄及已送出的用量通知；再次啟用從目前資料開始。清除資料與連線也會清除紀錄，已儲存的使用計劃保留。

## 重置確認與資料有效性

重置通知預設開啟，可關閉；需要總開關和該組時段的監控同時開啟。

只有曾觀測舊週期、收到較新的資料，且新資料時間已跨過舊重置時間、新的重置時間也向後推進，才視為來源確認新週期。只是倒數到零，不會假裝額度恢復或發出重置通知。首次接入、切換來源、重建設定紀錄只建立基準。時間微小漂移不會清除已提醒級別；來源提前調整未來重置時間也不視為重置。

重置與偏離若同時符合，合併在同一通知。離線跨過多個週期，只通知最新確認的週期，不補發每個錯過的週期。

資料超過 1 小時、時間在未來、缺少重置時間、重置已過卻未更新、週期長度不符、未知時段或示範資料，全部暫停判斷。相同或更舊的資料時間不重複判斷。設定頁會顯示暫停原因及有效資料對應的計劃／實際值。

Claude 的獨立檔案使用自己的 `generatedAt`，不會因 Codex 更新或 Google Drive 重讀舊檔而變新。只有檔案真的更新才可能得到新的 Claude 提醒；此功能不改變現有資料接入方式。完整快照匯入屬於切換主資料來源，重建主來源的重置基準。

## 通知與背景執行

沿用既有同步，不新增精確鬧鐘或另一組背景輪詢：一般背景約 15 分鐘、App 開啟或選用每分鐘模式時約 1 分鐘，仍可能因 Android 省電、網路及來源限制延後。提醒跟隨成功取得的新資料，不保證在跨越門檻的瞬間送達。

提醒使用獨立的 `quota_plan_silent_v1` 通知類別，預設 `IMPORTANCE_LOW`、無聲、不震動。Android 系統允許使用者改變類別設定，因此 App 會顯示目前權限及聲音狀態，提供系統設定入口。拒絕通知不影響計劃儲存及額度同步。

官方說明：[通知類別](https://developer.android.com/develop/ui/views/notifications/channels)、[通知權限](https://developer.android.com/develop/ui/views/notifications/notification-permission)。

## 開發與驗證

- `UsagePlan.java`：設定、序列化、時間分配計算。
- `AlertRules.java`：純 Java 提醒判斷與可持久化的最高級別紀錄。
- `QuotaAlerts.java`：各服務獨立時間、來源辨識、系統通知、設定與歷史儲存。
- `AlertSettingsActivity.java`：設定總覽及各時段的編輯頁。
- `QuotaStore.java`：成功同步或匯入後觸發判斷；不把提醒失敗當成資料更新失敗。
- `tests/UsagePlanTest.java`：205 個斷言，包括三種計劃、跨午夜、夏令時間、零比重、邊界、序列化與非法設定。
- `tests/AlertRulesTest.java`：41 個斷言，包括兩方向的門檻與加劇、回落、重新啟動後保留狀態、重置與時間修正、失序／過期資料、開關。

2026-10-20：Java 全部 323 個斷言及 Python 16 個測試通過；APK 編譯與 v2／v3 簽章驗證通過。受限環境的 Python 測試需把暫存資料夾設在專案內 `app/build/test-temp`，預設系統暫存位置的檔案替換曾失敗，改用專案暫存後通過。未修改 Claude 匯出程式。

尚無 Android 實機或模擬器測試，下列需要安裝後驗收：

1. Android 13 以上首次允許、拒絕通知、從系統恢復權限；停用單一通知類別後狀態可見，額度同步仍正常。
2. 無聲測試通知在通知列出現，無聲無震動，點擊可返回設定；系統改為有聲後，App 顯示對應狀態。
3. 四組設定各自保存，重新開啟 App 後保留；旋轉畫面、大字體、鍵盤彈出與返回放棄修改流程。
4. 用較新的測試來源資料依序超用 10、15、20 個百分點，只有 10、20 通知；回落再升到 20 不通知，再到 30 才通知。少用方向同樣測試。
5. 舊週期跨越重置後提供新週期資料，通知一次；重讀同一份資料不通知；無新資料時不宣稱重置。
6. Claude 過期但 Codex 最新時，只判斷 Codex；示範資料、關閉時段或總開關不送提醒。
